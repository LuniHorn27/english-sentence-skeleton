# 開發計畫：第 0、1 階段（草稿，待確認）

> 目標：做出一個**在自己電腦上就能用**的單句分析網頁，畫面和第五版草稿一樣，分析結果由程式自動產生。
> 原則：每一步完成後都有看得到的成果；標 ✅ 的地方要等你確認，才進行下一步。

---

## 範圍

**第 1 階段會做**

- 一次輸入**一個句子**（最多 300 字元）
- 骨架模式／詳細模式切換
- 主幹標籤：S、Vt、Vi、V、aux.、O、IO、DO、SC、OC
- 修飾語功能：「形容詞・修飾 X」「副詞・表時間／表地點／表方式…」
- 核心字加粗
- 句型＋完整公式（例如 `句型五：S + Vt + O + OC`）
- 點片語看說明
- 句子下方的文法重點卡（第一批約 10 張）
- 中文翻譯（Chrome／Edge 電腦版）
- 沒把握的部分標成「未分析」
- 電腦和手機都能正常顯示

**第 1 階段不做（留到之後）**

| 功能 | 放在哪個階段 |
|---|---|
| 子句「點開展開」 | 第 2 階段（第 1 階段先把子句整塊標成修飾語） |
| 整段文章 | 第 2 階段 |
| 錯誤回報按鈕 | 第 2 階段 |
| 放上網路 | 第 3 階段 |
| 查單字、列印、儲存 | 第 4 階段 |
| 拍照取字 | 第 5 階段 |

---

## 技術選擇

| 項目 | 選擇 | 原因 |
|---|---|---|
| 後端 | Python ＋ FastAPI | 文法分析程式都是 Python；你在商店專案用過 FastAPI |
| 文法分析程式 | Stanza 或 spaCy＋benepar | 第 0 階段實測後決定 |
| 前端 | 單純的 HTML／CSS／JavaScript | 雛形不需要框架，草稿的程式可以直接沿用 |
| 翻譯 | Chrome 內建 Translator API | 免費、資料不外傳；不支援的瀏覽器顯示提示 |
| 版本紀錄 | git | 改壞了可以退回上一版 |
| 費用 | 0 元 | 全部在自己電腦上執行 |

### 資料夾結構

```
english/
├── docs/            規格文件（標籤規則、這份計畫）
├── tests/           題庫與自動測試
├── backend/
│   ├── app.py       網頁伺服器
│   ├── analyzer/    分析引擎（呼叫分析程式 → 套規則 → 輸出結果）
│   ├── lexicons/    字表（連綴動詞、授與動詞、時間名詞…）
│   └── cards/       文法重點卡（一張卡一個檔案）
└── frontend/        網頁畫面（index.html、style.css、app.js）
```

## 第 0 階段：定規則、選工具

### 0-1　建立專案環境
- 建立上面的資料夾結構，啟用 git
- 安裝 Python 套件：FastAPI、Stanza、spaCy、benepar
- **特別確認**：benepar 已經 4 年沒更新，可能裝不起來。裝不起來就直接排除，只測 Stanza
- **完成後你會看到**：資料夾建好，一份「安裝結果」說明

### 0-2　題庫定稿，並分成「練習題」和「考試題」 ✅
- 你審核完 [題庫草稿-v3.md](題庫草稿-v3.md)，我依照你的意見修改成定稿
- **為什麼要分兩份**：寫規則時一直看著同一批句子，規則很容易變成「只會做這幾題」。所以要另外準備一份**寫規則時不看的考試題**，用來檢查規則在新句子上是否也管用
  - 練習題：現有的 41 句
  - 考試題：我再出 30 句，同樣請你審核。審核完就封存，寫規則時不看
- 把題庫轉成程式讀得懂的格式（`tests/gold.yaml`）
- **你要做的**：審核 41 句＋30 句

### 0-3　寫〈標籤規則〉規格書 ✅
- 把我們討論過的所有決定寫成一份正式文件（`docs/標籤規則.md`），包括：
  - 每個標籤的定義和判斷方式
  - 副詞功能的完整清單（表時間、表地點、表方式、表目的、表狀況、表路程、表語氣…）
  - 特殊句型：There is、祈使句、疑問句、進行式、A of B
  - 核心字的定義和例外
  - 什麼情況要標「未分析」
- 之後寫程式的時候，一律照這份文件做；文件沒寫到的情況，先問你
- **你要做的**：看過並確認

### 0-4　實測比較分析程式 ✅
- 用練習題 41 句，分別測試 Stanza 和 spaCy＋benepar
- 先寫一個很簡單的轉換程式，只轉主幹（S、V、O、IO、DO、SC、OC），比較兩者的準確度
- 比較項目：

  | 項目 | 說明 |
  |---|---|
  | 主幹準確度 | 在 41 句裡，主幹標對幾句 |
  | 片語邊界 | *in the blue shirt* 這類片語是否正確切成一塊 |
  | 速度 | 分析一句要多久 |
  | 安裝大小 | 將來放上網路時，免費主機裝不裝得下 |
  | 授權 | 能不能免費使用和公開 |
  | 維護狀況 | 最近是否還有更新 |

- **完成後你會看到**：一份比較報告，附上我的建議
- **你要做的**：決定用哪一個

### 0-5　定義資料格式
- **分析結果的格式**：每個片段有哪些欄位（文字、角色、功能、核心字、說明、對應的文法重點卡）
- **文法重點卡的格式**：跟草稿的區塊一樣（公式、小技巧、常見錯誤、補充、條列、例句），外加「什麼情況下要出現」的判斷條件
- **完成後你會看到**：2 句示範用的分析結果、1 張示範用的文法重點卡

### 0-6　列出第一批文法重點卡 ✅
- 預計 13 張：現在進行式、現在完成式、被動語態、There is／There are、祈使句、助動詞疑問句、授與動詞、連綴動詞、數量詞＋of＋名詞、單位詞（a glass of…）、find＋受詞＋形容詞、關係代名詞 who、感官動詞＋原形動詞
- **你要做的**：確認清單，或增減卡片

## 第 1 階段：單句雛形

### 1-1　做出空殼網頁
- 網頁伺服器可以在自己電腦上啟動，打開瀏覽器就看得到
- 分析功能先回傳**假資料**（直接用 0-5 的示範結果）
- **完成後你會看到**：打得開的網頁，輸入任何句子都會顯示示範句

### 1-2　完成畫面 ✅
- 把第五版草稿做成正式畫面：輸入框、分析按鈕、骨架／詳細切換、圖例、點片語看說明、文法重點卡
- 加上草稿沒有的狀態畫面：分析中、分析失敗、輸入太長、沒有輸入
- 手機寬度排版
- **資安**：使用者輸入的文字一律當成純文字顯示，不當成網頁程式碼執行（防止 XSS 攻擊）
- **完成後你會看到**：外觀跟最終版一樣，但內容還是假資料
- **你要做的**：在電腦和手機上看過，確認畫面

### 1-3　建立自動測試
- 寫一個測試程式：自動把題庫的句子丟進分析引擎，和標準答案比對
- 輸出一份報告，包括：
  - 各項目的正確率（主幹、句型、修飾語、核心字）
  - 每一句錯在哪裡（標準答案 vs 程式的答案）
- **先做測試、再寫規則**：之後每修改一條規則，就跑一次測試，確認分數沒有下降

### 1-4　分析引擎（一）：主幹與句型
- 用 0-4 選定的分析程式，找出主詞、動詞、受詞、補語
- 判斷 Vt／Vi／V，搭配字表（連綴動詞、授與動詞、「動詞＋受詞＋補語」類動詞）
- 找出助動詞 aux.
- 判斷句型、產生公式
- 處理特殊句型：There is、祈使句的 (You)、疑問句
- **目標**：練習題的主幹和句型正確率 ≥ 90%

### 1-5　分析引擎（二）：修飾語與核心字
- 切出片語的範圍（例如 *in the blue shirt* 是一塊）
- 判斷修飾語是「形容詞・修飾 X」還是「副詞・表…」
- 副詞的細分（表時間、表地點…）靠字表判斷，例如 *in the fall* 的 fall 在「季節」字表裡
- 找出核心字；遇到「數量詞＋of」就不標
- 子句先整塊標成修飾語（展開功能留到第 2 階段）
- **目標**：練習題的修飾語正確率 ≥ 80%

### 1-6　「未分析」機制
- 遇到以下情況，對應的片段標成灰色「未分析」，不硬猜：
  - 規則彼此矛盾（例如同時符合兩種判斷）
  - 分析程式的結果不合理（例如找不到主要動詞）
  - 超出第 1 階段範圍的句子（例如很多層的子句）
- 畫面上方顯示提示：「這句比較複雜，部分內容尚未分析」

### 1-7　說明文字與文法重點卡
- **片語說明**：用範本自動產生，例如「主詞，核心字是 ___。」「說明是『哪裡的』___。」
- **文法重點卡**：寫好第一批 10 張卡，並設定出現條件，例如「aux. 是 be 動詞，而且主要動詞是 V-ing → 現在進行式」
- **你要做的**：看過卡片內容

### 1-8　中文翻譯
- 使用 Chrome 內建翻譯
- 不支援的瀏覽器（Safari、手機版等）顯示：「目前的瀏覽器不支援自動翻譯，請使用電腦版 Chrome 或 Edge」
- 翻譯旁邊標註「機器翻譯」

### 1-9　用考試題檢查
- 第一次打開封存的 30 句考試題，跑自動測試
- 如果考試題分數比練習題低很多，表示規則只會做練習題，要回頭調整
- **目標**：考試題的主幹正確率 ≥ 85%

### 1-10　你實際試用 ✅
- 你自己輸入各種句子試用，把問題記下來
- 我修正問題，每次修正都跑測試，確認沒有弄壞其他地方
- **你要做的**：試用、回報問題

### 第 1 階段完成的條件
- [ ] 練習題：主幹、句型正確率 ≥ 90%，修飾語 ≥ 80%
- [ ] 考試題：主幹正確率 ≥ 85%
- [ ] 分析一句在 2 秒以內
- [ ] 任何輸入都不會讓網頁當掉（空白、亂碼、超長、非英文）
- [ ] 電腦版 Chrome 和手機寬度都正常顯示
- [ ] 你試用後確認可以進入第 2 階段

> 正確率目標是初步設定，第 0 階段實測之後會依照實際數字再調整。

## 風險與對策

| 風險 | 對策 |
|---|---|
| benepar 裝不起來 | 0-1 就先確認；改用 Stanza |
| 規則越寫越多、寫不完 | 範圍限定在題庫程度的單句；超出範圍就標「未分析」 |
| 規則只會做練習題 | 考試題封存，最後才拿出來檢查 |
| 分析程式本身判斷錯 | 用字表做第二道確認，例如授與動詞字表 |
| 翻譯只支援部分瀏覽器 | 先標示清楚；第 3 階段再考慮加入 Gemini 免費額度當備案 |
