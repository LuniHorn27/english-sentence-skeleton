# 前端改版設計（品牌視覺方向 C）

- 日期：2026-10-06
- 分支：`redesign-brand-c`（完成後先不合進 main，使用者確認 OK 才開 PR）
- 狀態：設計文件，等使用者審核

## 一句話結論

整站改成「奶油色底＋墨黑介面，飽滿的顏色只留給 S、V、O、C」。俏皮感來自偵探貓的表情和「骨架從完整句子裡浮現」的招牌動畫，不靠更多顏色、網路字體或大動畫。分四段做，第一段是首頁和分析結果。

## 一、為什麼改、改成怎樣才算成功

使用者不滿意的四件事：看不出品牌個性、四個頁面不一致、想要更飽滿俏皮的視覺、版面和流程不順（首頁太雜、分析結果不好讀、手機不好用）。

成功的樣子：

1. 手機打開首頁，第一個畫面同時看得到輸入框和一句分析好的範例，不用往下滑。
2. 按下分析後，結果直接出現在範例的位置，不用往下找。
3. 長句子在手機上仍然看得出是一整句話，骨架一眼看得出來。
4. 畫面上除了 logo，有顏色的東西只有 S、V、O、C；看到藍色就是主詞。
5. 四個頁面共用同一個頁首、同一種標題區和同樣的寬度。
6. 品質以 Awwwards、Webby、FWA 得獎網站為標準，從排版、留白、視覺層級、色彩、動效、微互動、響應式、原創性八個面向自檢到沒有明顯可提升之處。

## 四、第一段詳細設計

### 4-1 配色和基本樣式

`frontend/style.css` 開頭的顏色變數整組換掉，全站都從這裡取色，不在各處寫死色碼。

| 用途 | 顏色 | 說明 |
|---|---|---|
| 頁面背景 | 奶油色 `#fdf6e8` | 取自放大鏡鏡片的暖色調 |
| 卡片 | 白 `#ffffff` | 分析結果、輸入框 |
| 主要文字、按鈕、連結 | 墨黑 `#1a1d23` | 品牌原本的墨黑 |
| 次要文字 | 暖灰 `#5c5444` 左右 | 實作時檢查對比至少 4.5:1 |
| 線條 | 淡暖灰 `#eadfca` 左右 | 分隔線、卡片邊 |
| 修飾語 | 灰，約 `#6f695c` | 退場後的顏色，仍要讀得到：對比至少 4.5（示意圖用的 `#8a8374` 只有 3.8，太淡） |
| S／V／O／C | 品牌鮮豔版 `#2f6fed`／`#e0603a`／`#1a9a74`／`#f2b52b` | 見第六節待確認 3：可能要微調深一點才過對比 |

按鈕：主要按鈕（分析）是墨黑實心、白字、全圓角；次要按鈕是白底、細框、墨黑字。整頁只有一個實心主要按鈕。連結是墨黑字加底線。

圓角、間距、字級統一成少數幾個固定數值（例如間距只用 4、8、12、16、24、32、48），寫成變數，四個頁面共用。

### 4-2 頁首（四頁共用）

- 電腦：左邊貓 logo＋「英文句子骨架分析」，右邊依序是「何謂五大句型？」「測驗小遊戲」「關於此網站」「分享」。
- 手機（寬度 768 px 以下）：左邊貓 logo＋全名，右邊漢堡按鈕；點開後從頁首下方往下展開四個項目，再點一次或點旁邊就收起來。
- 現在所在的頁面，連結要標出來（例如加粗或底線變粗）。
- 漢堡選單用鍵盤也能操作，螢幕閱讀器念得出「選單」「關閉選單」。
- 四個頁面的頁首目前各寫一份，這次改成一樣的結構，以後只要改一處就能套用到全部頁面的做法留到第二段再評估，第一段先確保四份內容一致。

### 4-3 首頁

由上到下：

1. 頁首
2. 標題「句子落落長看不懂？」和現有標語（全部保留，不刪字）
3. 輸入框：白底、墨黑細框、大圓角；右下是「分析」按鈕；左下是字數和「最近分析（N）」入口（點了展開最近分析清單）
4. 範例句子按鈕：手機上排成一列，可以左右滑；電腦上一列排開
5. 分析結果區：還沒輸入時顯示「範例」分析（The teacher showed us a picture.，旁邊是一般表情的偵探貓）；按下分析後，這一區原地換成使用者的句子
6. 分享、列印講義、回饋三個按鈕（刪掉「Hi, there!」）
7. 頁尾：回饋入口、請喝咖啡、免責說明，合成一個安靜的區塊

手機上第 2～5 項的開頭要在第一個畫面裡看得到（以 375×812 的螢幕為準）。按下分析後，如果結果的開頭不在畫面內，畫面自動平順地捲到結果卡的頂端。

範例分析不呼叫伺服器，直接寫在網頁裡，打開首頁就有，網路慢也不用等。

### 4-4 分析結果卡

卡片由上到下：

1. 第一列：左邊句型公式（圓角長條，例如「句型四 S＋Vt＋O＋OC」）；右邊是朗讀、回報兩個圖示按鈕
2. 句子：整句照原本順序像文章一樣換行、靠左
   - 主要成分（S、V、O、C 及其細分 Vt、Vi、IO、DO、SC、OC）：整段畫上該成分顏色的實心底線；核心字上方浮著一個圓形標籤，標籤和字之間留一點空隙
   - 所有底線畫在同一條基準線上；標籤不能壓到上一行的字或句型公式
   - 修飾語：文字變灰，不畫顏色；點一下顯示「形容詞子句・修飾 book」這類說明，子句照現在的方式可以展開
   - 助動詞、真主詞等「不算進公式」的部分：維持現在的虛線規則
   - 複句（兩個子句加連接詞）、被省略的字「( )」、可能拼錯字的提示、「這句可能分析錯了」提示：保留現有功能，換成新樣式
3. 「中文翻譯」小標題＋翻譯（「機器翻譯」小標籤保留，誠實告知是程式翻的）
4. 「文法重點」小標題＋一排標題按鈕，點了在下方展開說明（說明內容和現在相同）
5. 片語卡等其他現有內容：保留，換成新樣式

「骨架模式／詳細模式」切換保留：骨架模式就是上面的樣子；詳細模式下，所有修飾語的說明直接顯示在句子上方，不用點。

標籤彼此太靠近時（例如 I give you 這種短字相連），要自動錯開，不可以疊在一起。現在程式裡已經有處理標籤重疊的功能（`fixLabelOverlap`），改寫來處理圓形標籤。

### 4-5 招牌動畫：骨架浮現

1. 結果出現時，先顯示完整的句子（全部墨黑）。
2. 約 0.5 秒後，修飾語慢慢變灰。
3. 接著 S、V、O、C 依句子順序，每個成分間隔約 0.25 秒，標籤彈出、底線從左畫到右。
4. 整段約 1.5 秒內結束，每次新的分析只播一次；從「最近分析」或分享連結打開時也播。
5. 使用者的系統設定了「減少動態」時，直接顯示最後的樣子，不播動畫。
6. 列印時不播動畫，直接印最後的樣子。

### 4-6 偵探貓（配角）

同一隻貓，只改放大鏡裡的眼睛，不加嘴巴和腮紅：

| 狀態 | 眼睛 | 用在哪裡 |
|---|---|---|
| 等你貼句子 | 一般的大眼睛 | 首頁範例卡 |
| 辦案中 | 眼睛左右看 | 分析中 |
| 看走眼 | 鏡片裡變成問號 | 出錯訊息 |

第一段先用這三種；「破案」等其他表情在第三段定稿。

### 4-7 圖示

頁首和分析結果卡上的 emoji（🔗🖨️💬🚩🕘🧪 等）換成線條圖示。圖示直接畫在網頁裡（SVG），不另外載入圖示字型，網路慢也不受影響。其他頁面的 emoji 在第三段處理。

| 選單 | 五大句型 | 何謂五大句型？ |

### 4-9 品牌規範要改的地方（使用者已同意）

- 主藍：從「標誌底色、主要按鈕、連結」改成「標誌底色、S 主詞」。
- 新增：主要按鈕和連結用墨黑。
- 新增：頁面背景改成奶油色 `#fdf6e8`。
- 網頁標記用色：從現在的淡色底（`#e6f1fb` 等）改成鮮豔版四色。
- 深色模式：註明「暫停，之後再做」。

### 4-10 暫停深色模式

現在的網站會跟著系統設定切深色。改版後先固定淺色：拿掉深色的顏色設定，告訴瀏覽器這個網站只有淺色，避免系統開深色時出現一半深一半淺的畫面。這是使用者同意拿掉的功能。

### 4-11 列印講義

改版後列印功能要照樣能用：白底、不印頁首選單和按鈕、不播動畫、四色和底線印得出來。完整的列印版面調整放在第四段。

## 六、待確認（看這份文件時一起回答）

1. **核心字下方的「核心」兩個字要不要拿掉？** 現在每個核心字下面都有小小的「核心」。改版後，圓形標籤就浮在核心字正上方，已經標出哪個是核心。建議拿掉，畫面更乾淨。
2. **修飾語不畫虛線。** 示意圖裡修飾語是灰色加虛線，但現在的規則裡，虛線代表「不算進公式」（助動詞、真主詞）。兩個意思用同一種線會混淆，所以建議修飾語只變灰、不畫線，可以點的提示改用滑過時出現淡底色。
3. **四色可能要微調深一點。** 實際算過對比：S 藍 `#2f6fed` 配白字 4.55，剛好過小字標準 4.5；V 橘紅 `#e0603a`、O 綠 `#1a9a74` 配白字都只有約 3.6，不夠；C 黃 `#f2b52b` 的底線在白底上只有 1.84，低於圖形標準 3。建議做法：標籤圓圈和底線的顏色微調深一點（肉眼幾乎看不出差別），C 的標籤圓圈維持鮮黃配深色字，底線改用深一點的琥珀色。調整後的色碼會給使用者看過，同意了再同步改品牌規範。

## 七、怎麼驗證

每完成一部分，就在本機網站上實際操作檢查：

- 螢幕寬度 375、768、1280 都看過：沒有橫向捲動、手機左右至少留 16 px、手機上按鈕至少 44 px 方便點
- 用不同長度的句子測：短句（Birds fly.）、雙受詞、長修飾語子句、複句、被動、祈使句、有拼錯字的句子
- 標籤不重疊、底線在同一條線上、標籤不碰到公式
- 鍵盤可以操作漢堡選單、文法重點展開、模式切換；焦點看得到
- 開啟「減少動態」時不播動畫
- 列印預覽正常
- 文字和背景的對比都達標
- 跑 `/check` 確認分析功能沒有被改壞

八面向自檢：每一輪都截圖，依排版、留白、視覺層級、色彩、動效、微互動、響應式、原創性逐項寫「看到的問題 → 改了什麼」，改到沒有明顯可提升之處，再交給使用者看。

## 八、風險

- **標籤重疊：** 短字相連時圓形標籤會擠在一起，要靠自動錯開處理，最難的是手機窄畫面加長句。
- **改動範圍大：** `style.css` 幾乎整份重寫、`app.js` 的句子顯示要改。分析功能（`renderSentence` 一帶）要特別小心，靠多種句型實際測試把關。
- **多個對話同時開發：** 主資料夾常有其他對話在改，所以這次全部在獨立 worktree 和分支上做，合併前再同步 main 的新變更。
